## 一、修掉「有会员却听不了会员曲」的根因（本版最重要的一项）

**现象**：账号显示酷狗 VIP / SVIP，手机上的酷狗概念版能正常听，但本客户端点林俊杰等会员曲播放失败，
提示「酷狗需要官方安全验证」。

**排查结论**（逐步实测得到）：

1. 概念版「畅听VIP」（`user_vip_detail` 里 `product_type: 'tvip'`）**只覆盖标准音质（128k）**；
   请求无损 / 320 时 `/v5/url` 返回 `status: 2` + `fail_process: ['pkg', 'buy']`（权限拒绝）。
2. 本客户端对酷狗的**默认音质是「无损 FLAC」**，于是每首会员曲都请求 flac → 概念版拒绝 →
   旧逻辑判成「取不到地址」→ **回退标准版接口**（概念版 token 在标准版不通用）→ 界面报「需要官方安全验证」。

**修复**（`kugou-lite.js` → `liteSongUrl`）：

- 高档位（无损 / 320）被权限拒绝时，**用主 hash 再请求一次 `quality=128`**，成功即按标准音质播放，
  返回 `level: 'standard'` + `degraded: true`；行为对齐概念版 App（它会静默降级）。
- 128 也拿不到时，按 `fail_process` 给出准确原因：`buy` → 「需购买专辑/单曲」、`pkg` → 「需豪华 VIP」，
  并给 `reason: 'vip_required'`，**不再回退标准版**（白跑一趟还给出误导文案）。
- 前端零改动即可用：`public/js/modules/05-playback/13-playback-start-audio.js` 原本就有
  `playbackQualityWasDowngraded()` → `markPlaybackQualityRuntimeCap()`（记住**单曲**音质上限）
  + 「酷狗音质自动降级：请求 无损 FLAC，实际播放 标准 · 128 kbps」提示。

## 二、补齐奖励链路：听歌就自动领 VIP（含**时长 VIP**）

概念版每日奖励共三种，**它们给的不是同一种 VIP**——这一层是本版新增的能力：

| 奖励 | 接口 | 额度 | 实际效果 |
| --- | --- | --- | --- |
| 每日领取 | `/youth/v1/recharge/receive_vip_listen_song` | 1 天 1 次 | 给 **tvip**（畅听）→ 会员曲只能标准音质 |
| 听歌奖励 | `/youth/v2/report/listen_song` | 1 天 1 次 | 上报一首自然播完的歌 |
| **广告奖励（本版新增）** | `/youth/v1/ad/play_report` | **8 次/天，每次 +3 小时** | 给 **svip 档位时长 → 直接解锁无损 / 320** |

**实测效果**：听歌触发后自动补领到 8/8，账号档位由 `tvip` 升为 **`svip`（is_vip: 1，到期 +24h）**，
此后会员曲请求无损直接返回 `extName: 'flac'`，经应用音频代理读取到 `fLaC` 文件头——**即本版同时解决了
「会员曲只能听 128」的另一半**。

**实现**：

- 新增 `kugou-server/module/youth_ad_play_report.js`：`POST /youth/v1/ad/play_report`，
  body `{ ad_id: 12307537187, play_start, play_end }`（毫秒时间戳，默认上报一条 30 秒广告播放），
  响应 `data.{total: 8, done, remain, remain_vip_hour, award_vip_hour: 3}`，次数用尽码 `30002`。
  行为与节奏对齐 EchoMusic 的 `echomusic-kugou-reward` 插件（30 秒间隔、每天 8 次上限）。
- `server.js` 新增 `claimKugouAdReward()`（落盘 `kugou-reward-state.json` 的 `adReward`，
  按自然日 + userid 去重）与 `pumpKugouAdReward()`（后台每 30 秒补领一次，直到当天用尽，**不阻塞请求**）；
  在 `/api/kugou/song/url`（每次取播放地址＝听歌）与每日领取一起自动触发。
- 听歌奖励上报维持原状（前端在自然播完时自动调用，服务端按日去重）。
- `kugou-server/module/youth_day_vip.js` 的 `source_id` 改为接受入参（此前硬编码 90139，
  90137 兜底分支永远走不到）。
- 开关：启动参数加 `KUGOU_AD_REWARD=0` 可整体关闭广告奖励。

## 三、账号面板「今日奖励」区块 + 入口按钮（兜底完整）

- **入口**（两项）：顶部右上角 `今日奖励 8/8` 胶囊按钮（位于主页图标与头像之间，徽标实时显示当日进度）；
  登录接入弹窗头部「今日奖励」按钮。
  ⚠️ 排查发现：`showUserModal()`（账号信息弹窗）在本仓库**没有任何调用者**，等于此前该弹窗在主界面点不出来；
  本版一并把它接上了。
- **面板**（账号信息弹窗内）四行数据：会员（档位 + 到期）、广告奖励（`8/8 已领满`）、
  听歌奖励、每日领取；底部 `补领奖励` / `刷新` 两个按钮。点补领后每 10 秒刷新一次进度（最多 3 分钟）。
- **服务端汇总接口** `/api/kugou/vip/reward-summary`：一次返回上述全部信息；**任何一步失败都不抛错**，
  返回 200 + `degraded` / `note` 的降级结果，线上会员状态读不到时退回本地账本。
- **兜底清单**：未登录 / 非酷狗平台整块隐藏；接口失败保留占位并提示可重试（按钮仍可点）；
  广告奖励被关闭时按钮隐藏、文案「已关闭」；补领中按钮禁用防重复；轮询连续失败 3 次自动停止；
  渲染全程 `try/catch`；所有挂接点带 `typeof === 'function'` 守卫。

## 六、验证情况（实测记录）

**播放与会员（本机账号实测）**

- 修复前：`quality=lossless` 请求会员曲 → `playable: false` + `reason: 'verification_required'`（界面提示需安全验证）。
- 修复后同一请求 → `playable: true`、`level: 'standard'`、`degraded: true`，降级耗时 244 ms（无损）/
  92 ms（320），均在一次额外请求内完成。
- 免费歌曲不受影响：`quality=lossless` 仍返回真无损（`bitRate: 789000`，`extName: 'flac'`）。
- 广告奖励补领：`done 8/8`，`remain_vip_hour 21 → 0`；账号档位 `tvip → svip`，
  `vipExpireAt` 由 `2026-09-27 10:45` 变为 `2026-09-27 11:12`（+24 小时累计）。
- 无损真播：`/api/kugou/song/url?quality=lossless` 返回 `.flac` 直链，经 `/api/audio` 代理
  读到 `Content-Type: audio/flac` 与前 4 字节 `fLaC`。
- 需购买类歌曲：《交换余生》`fail_process: ['buy']`，128 亦不开放，本版按实提示「需购买专辑/单曲」。

**搜索 / 歌词 / 扫码 / 奖励账本**

- 搜索：`林俊杰` 返回的条目 `hq/sq/res` hash 由空变为有值（例：`美人鱼` → `sq=A04425DB`）。
- 歌词：`不为谁而作的歌` 返回 1046 字符 lyric。
- 扫码：`/api/login/qr/key` 取到 key，`/api/login/qr/check` 返回 `code: 801 等待扫码`（新模块带 `dev` 参数可用）。
- 账本：`dailyVip` ok / `adReward 8/8` / `listenReport 今日已领取` 三条落盘记录齐备。

**界面（几何度量 + 视觉复核）**

- 奖励面板：四行等高 `23px`；四个数值右边缘**同一点（829）**；两个按钮等宽并填满行宽；
  卡片上下间距 `14 / 14`；无溢出（`scrollWidth == clientWidth`）。
- 顶部入口胶囊：与左右圆钮等高 `44 / 44 / 44`，左右间距 `10 / 10`，垂直中心线 `46 / 46 / 46`。
- 兜底实测：模拟接口失败 → 提示「读取失败，点击补领可重试」且按钮可点；模拟未登录 → 两个入口 `hidden`；
  广告奖励关闭 → 徽标「关闭」、按钮隐藏；补领中 → 按钮禁用显示「补领中…」。

**接口与自动化测试**

- 9 个相关路由全部 200：`login/status`、`vip/reward-summary`、`vip/reward-state`、
  `user/purchased`（songs/albums）、`search`、`lyric`、`song/url`、`login/qr/key`。

## 七、已知限制

- **数字专辑（`fail_process: ['buy']`）** 如《交换余生》即使降到 128 也不开放，本版只能给出准确提示，无法播放。
- **广告奖励**是「上报一条 30 秒广告播放」以领取概念版 VIP 时长，节奏与原版插件一致（30 秒间隔、每天 8 次）；
  如不希望自动执行，用 `KUGOU_AD_REWARD=0` 关闭。
- **已购查询**返回体（`data.goods` 的字段名）在账号「0 购买」的情况下无法实测，因此只在**确实匹配到已购专辑**时
  才在播放失败响应里补 `purchasedAlbum: true`，不做「未购买」的负面断言。
- **无损/320 取决于账号当天的时长 VIP**：仅领「每日领取（tvip）」时会员曲仍是标准音质，
  这是酷狗侧的档位限制，不是客户端缺陷。
- 上游已停更；本版基线仍为上游 v2.2.0，上游随后的两个「停更声明」文档提交未并入。
- macOS / Windows 未验证（本适配版只面向 Linux）。

## 八、安装与构建

```bash
# 安装
sudo dpkg -i mineradio_2.2.1_amd64.deb

# 如提示缺少依赖
sudo apt-get -f install

# 从源码构建
git clone https://github.com/YannZhou/Mineradio.git && cd Mineradio
npm install --include=dev
node node_modules/electron/install.js     # 若 Electron 二进制未随包下载
npm start                                 # 开发模式运行
npm run build:linux                       # 产出 deb
```

> 开发模式下若从终端脚本启动，需要 `env -u ELECTRON_RUN_AS_NODE`（否则 Electron 会以 Node 模式启动）。
